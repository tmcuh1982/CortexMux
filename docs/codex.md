# Codex subscription provider (0.6.0 release candidate)

`codex` is an explicit opt-in provider using the official local
`codex app-server --listen stdio://` protocol. It sends supplied text to the
Codex service using a ChatGPT subscription. It is distinct from `openai`,
which uses an API key and API billing. Neither provider falls back to the other.
Enabling Codex authorizes its service traffic; the general web fetcher remains
independent and disabled by default.

## Compatibility and prerequisites

Install Codex CLI yourself. This adapter accepts **codex-cli 0.140.0** only,
checked before starting the server. No installation, upgrade, process launch,
or login happens at import. New CLI versions require protocol/isolation review.
The implementation uses stable v2 fields from JSON schemas generated by that
binary; it does not opt into experimental APIs. Official documentation describes
App Server as evolving: this is an experimental integration, not a promise of
compatibility with every Codex distribution or managed account.

Verified locally: version command, schema generation, initialize/initialized,
account/read without credentials, and process cleanup. Authenticated generation
requires the optional integration test; it was not used to consume an account's
quota during development.

References checked on 2026-09-10:

- [App Server protocol, auth, turns, and output schemas](https://learn.chatgpt.com/docs/app-server)
- [ChatGPT login and credential storage](https://learn.chatgpt.com/docs/auth)

## Configuration and isolation

```toml
[providers.codex]
enabled = true
executable = "/absolute/path/to/codex"
auth_directory = "/application-owned/private/cortexmux-codex"
timeout_seconds = 120
startup_timeout_seconds = 15
shutdown_timeout_seconds = 5
```

The default auth directory is the platform application-data directory for
`cortexmux`, under `codex`. CortexMux passes this directory as the child's
`CODEX_HOME` and selects Codex file credential storage. **Codex** writes and
refreshes its own `auth.json`; CortexMux never opens or copies it. Protect this
directory as credential storage and exclude it from source control and backups
that are shared publicly. Do not put it inside a repository. The adapter rejects
`~/.codex`, the parent's `CODEX_HOME`, personal config files, plugins, hooks and
custom skills in this directory. Codex's automatically generated `.system`
skills directory is permitted for subsequent starts.

Use a distinct directory per consuming application. `codex_logout()` clears
credentials for every process sharing that directory. It does not log out the
usual CLI/desktop home, but choosing another application's directory would
share that application's login/logout scope. Closing CortexMux preserves login.
OAuth URLs and device codes are intended for the application's login UI only;
do not log them. No token input or external-token refresh API is exposed.

The child uses a fresh temporary working directory, a small environment allowlist
(no API keys, token variables, endpoint overrides or workload identity), fixed
OpenAI provider selection, `forced_login_method=chatgpt`, read-only sandbox,
network-disabled command sandbox, `approval_policy=never` and user reviewer.
Project documents, shell execution, shell snapshots, web search, apps, hooks,
remote plugins, memories, and multi-agent features are disabled through explicit
settings. No custom MCP servers are configured. Thread creation verifies the
returned sandbox, provider, reviewer, model and absence of instruction sources.
Every server-initiated permission/tool request is rejected, and unexpected tool
items fail the generation. No shell command is constructed or approved.

**There is no verified absolute "text only, zero tools" guarantee in the stable
0.140.0 protocol.** Built-in skills/tools and administrator-managed configuration
may remain; a read-only sandbox alone is not complete filesystem isolation.
Tool-item rejection observes an attempted action and cannot undo it. Stronger
isolation requires an externally controlled OS/container boundary. Consequently
`strict_no_tools` is false and `require_no_tools=True` is the default: generation
fails before submitting a turn. Set `require_no_tools=False` on a request only
when the consuming application accepts these limitations. This is never an
implicit permission escalation.

## API and capabilities

- `codex_account()` / `acodex_account()`: sanitized connection, email and plan.
- `codex_login_start(device_code=False)`: URL-based managed ChatGPT login.
  With `device_code=True`, return the official verification URL and user code
  (requires device login enabled on the account).
- `codex_login_result(login_id, timeout=300)`: wait for success/failure, including
  notifications arriving before the login-start response. A waiting timeout
  does not cancel login; call `codex_login_cancel(login_id)` explicitly.
- `codex_logout()` and `codex_rate_limits()`: dedicated logout and usage windows.
- All account operations have an `a`-prefixed asynchronous equivalent.
- `list_models("codex")`: current catalog with exact identifiers and advertised
  reasoning efforts. Choose a model explicitly. Unsupported options/efforts and
  model substitutions fail before generation. API temperature, token budgets,
  verbosity and service tiers are not assumed to work here.
- `generate`, `chat`, `structured`, and their asynchronous variants use existing
  response models. `structured` requires `json_schema` or a Pydantic response
  model, passes `outputSchema`, and validates again with CortexMux's supported
  JSON Schema subset. It never executes returned JSON. No prompt-only JSON claim.
- `stream(request)` / `astream(request)` accept a typed request. Text events have
  `raw_metadata.event` of `progress`, `delta` or `completed`. Progress contains no
  reasoning text. The terminal event contains the full final answer (do not
  append it to accumulated deltas). Errors raise typed exceptions. Structured
  streams emit unvalidated draft chunks and a validated completion only.
  Explicitly close an iterator when breaking early (`contextlib.aclosing` for
  async use, `contextlib.closing` for sync use).
- Responses carry `thread_id` and `turn_id` in `raw_metadata`, plus the normalized
  CortexMux request id and actual thread-selected model. No cost is invented.

Each independent request starts a fresh ephemeral thread. To retain history,
set `persist_conversation=True`; use its returned `thread_id` as
`conversation_id` on later requests in the **same CortexMux instance**. Model and
initial system instructions remain fixed. Arbitrary threads from other instances
are deliberately not resumed. Persistent transcripts remain in the dedicated
Codex home; CortexMux does not delete them automatically. Generation is serialized
per provider; use separate instances when independent concurrent processes are
needed. Do not mix sync and async use of one instance across event loops.

Task cancellation, early stream closure and timeouts send `turn/interrupt` when
the turn id is known. If submission outcome is unknown, the process is stopped.
No CortexMux retry is performed. Codex's internal service retry policy is owned
by Codex, not this adapter. A cancelled conversation is invalidated locally.
Unknown-outcome/process errors require a new CortexMux instance. Always close
CortexMux using its sync/async context manager.

`CodexError.context["reason"]` distinguishes `executable_missing`,
`incompatible_version`, `connection_required`, `connection_expired`,
`quota_reached`, `permission_required`, `timeout`, `cancelled`, and
`invalid_response`, plus explicit lifecycle/isolation/limit failures.
Unavailable models use `ModelNotFoundError`; schema failures retain
`StructuredOutputValidationError`. Server text and stderr are never attached
as diagnostics. Unclassified server failures use `ProviderResponseError`, not a
guessed auth/quota diagnosis. A healthcheck never starts a generation.

Usage windows retain unknown fields as `None`; `used_percent` means consumed,
`window_duration_mins` is minutes, and `resets_at` is a Unix timestamp in seconds.
Prefer `by_limit_id` when supplied, otherwise `rate_limits`. Subscription limits
and account eligibility govern usage; API credit balances do not apply.

## UniversRobot and release delivery

See [the minimal example](../examples/codex_universrobot.py). UniversRobot must
install/copy the approved official CortexMux release into
`UniversRobot/Tools/External/CortexMux/` using its existing release process.
Do not use an editable install, symlink, `PYTHONPATH` pointing to this checkout,
or a development-path dependency in UniversRobot.

Candidate version: `0.6.0rc1`. Build a wheel and source archive with
`python -m build`, then `twine check dist/*`. The existing tag-triggered workflow
uploads distribution artifacts. This change does not create a tag, publish a
release or change UniversRobot. Publication requires separate authorization.

Offline tests use a fake executable with the same JSONL lifecycle. Optional live
test (uses subscription quota; never enabled by default):

```sh
CORTEXMUX_CODEX_INTEGRATION=1 \
CORTEXMUX_CODEX_AUTH_DIRECTORY=/dedicated/already-connected/home \
CORTEXMUX_CODEX_MODEL=an-exact-discovered-model \
pytest -q tests/integration/test_codex_subscription.py
```
